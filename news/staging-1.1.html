6703OS-staging-1.1 in staging testing

The staging-1.1 build is currently used to test 6703OS as a server for the home business. It includes Linux kernel 6.16.1, and hosting validation is ongoing. The available software notes do not document CVE fixes for this build.

Hosting stack

  • Docker: runs the website and supporting services in containers.
  • Nginx: serves as the web server and reverse proxy.
  • Cloudflare: provide DNS and, when configured, edge caching and protective services.
  • Prometheus: collect service and host metrics.
  • Grafana: display monitoring dashboards.

Test hardware

  • Memory: 8 GB RAM.
  • Storage: 256 GB.
  • Processor: Intel Core i5, 10th generation.

Request-load testing

In a dedicated staging environment, generate authorized synthetic requests against the test website. Increase request volume in measured stages while monitoring response times, error rates, CPU and memory use, disk activity, and service health in Prometheus and Grafana. Record the tested request rate and the point at which performance or reliability degrades.

Controlled DDoS-resilience simulation

Use only a private, isolated test network and systems explicitly designated for this exercise. Simulate a bounded burst of ordinary application requests from approved test clients, with a fixed rate and duration, an operator present, and a clear stop condition. Do not send traffic to unrelated or public third-party systems, use spoofed traffic, or use reflection or amplification techniques. If exercising Cloudflare protections, use an authorized staging hostname and coordinate the test with the account owner and provider requirements.

Expected testing time

Estimated testing period: 3 months. This is an estimate for hosting, load, and resilience testing, not a guaranteed release date.

Results and status

Current result: Pending. No load-test or resilience results have been measured or confirmed yet. After testing, publish the environment, request profile, observed metrics, errors, and any limitations here.
